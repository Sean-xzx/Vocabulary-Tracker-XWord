## v0.2

- 2026-09-23 / 第三部分 A：D:\WSL 里只有一个空的子文件夹 Ubuntu-22.04（没有任何文件）；删除被权限配置拦下（“系统路径受保护”），按要求跳过，不再尝试。~/.wslconfig 存在，但最后修改于 2026-06-11，早于上一轮会话，不是上一轮留下的；两个 WSL 发行版（Ubuntu-22.04、Ubuntu）都是 Stopped、版本 2。全部没动 / 只读检查。
- 2026-09-23 / ECDICT 从官方 raw.githubusercontent.com 下载；第一次连接失败后，下载脚本增加了 GitHub API 的 blob 接口作为第二来源（jsDelivr 对超过 50 MB 的文件返回 403，gitee 镜像 404）。校验用 GitHub API 给出的 git blob SHA（逐字节一致），再加表头和 ability / go / went / abandon 抽查 / 比“抽查几条”更严格，任何来源下载的文件都能证明与官方仓库一致。
- 2026-09-23 / 词典裁剪结果：CSV 770,611 行，有中文释义 768,739 条；必须保留 19,358 条（带考试标签 14,942、牛津核心 3,461、柯林斯星级 13,633，三类有重叠）；再补充 652,513 条，共 671,871 条，压缩后 14,999,974 字节（按 15,000,000 字节算上限，两种“MB”口径都不超）。补充的前 39,779 条按 frq（其次 bnc）排序；ECDICT 里有词频数据的词只有这么多，全部加入后才 2 MB。之后按“单个英文单词且有音标 → 单个英文单词且有词性释义 → 只有领域释义的单词 → 有词性释义的词组 → 其余”分档、同档内词越短越优先继续补，直到接近 15 MB / 需求要求“按词频补充到接近 15 MB”，但词频数据只覆盖 5.9 万词；这样既满足大小要求，又让“词典里没有这个词”尽量少出现，排序也尽量把常见的形式放前面。
- 2026-09-23 / 词典文件仍是合法的 JSON，但每个词条独占一行、按小写单词排序；主进程只把它解压成 Buffer（zlib 在线程池里做）并记下每行位置，查询时二分查找、只解析用到的二十来行 / 整体 JSON.parse 要阻塞主进程约 0.5 秒、堆内存多占约 200 MB；现在加载时主线程只花几十毫秒扫描换行，常驻内存约 50 MB，单次查询不到 1 ms。
- 2026-09-23 / 词典在页面 did-finish-load 之后开始加载；加载完成前 dictLookup 返回 loading，加载失败返回 unavailable；日志记一条“词典已加载：N 条，用时 X ms；自检 ability：found” / 不阻塞窗口显示；冒烟测试时打包版没有调试端口，靠这条日志确认“词典能加载、查询正常”。
